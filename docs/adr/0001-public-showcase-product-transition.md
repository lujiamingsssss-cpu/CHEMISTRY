# ADR 0001：公开展示前台与化工询盘工作台分离

Status: Accepted
Date: 2026-08-03

## 背景

仓库原有 Chemical Trade AI Copilot 面向内部化工外贸人员，以受控 TDS/SDS 检索、证据门禁和英文回复草稿为核心。新的南京睿扬光电公开展示 Demo 面向外部客户，需要建立品牌理解、展示光学材料与器件能力、提供材料浏览和技术需求入口。

两者的用户、领域、信息架构、视觉语言和核心成功标准不同。直接在旧 Streamlit 工作台上改造会继承不适合公开展示的产品模型；删除旧系统又会破坏已经验证的证据治理能力和 Git 历史。

## 备选方案

### A. 原地改造旧 Streamlit 前台

复用启动方式和部分 Python 链路，但会把内部询盘工作台与公开品牌站耦合，页面结构和视觉能力也难以满足新的展示目标。

### B. 删除旧系统后重建

仓库表面更简单，但会失去既有代码、测试、证据门禁和受控资料扩展能力，回退成本高。

### C. 同仓保留旧系统，新建隔离展示前台

两套产品保持独立入口、样式和运行边界；只在出现真实调用方和失败案例后复用旧系统的证据能力。

## 决定

采用方案 C：

- 保留 Chemical Trade AI Copilot 的代码、测试、资料清单和索引边界；其稳定约束记录在 `PROJECT_SPEC.md`，界面遵循 `docs/UI_STYLE_GUIDE.md`。
- 新公开展示前台独立组织页面、资产、样式和交互，遵循 `docs/SHOWCASE_UI_STYLE_GUIDE.md`。
- 第一阶段不迁移旧 RAG，也不建立共享平台层。未来只有具体公开展示功能需要证据检索，且现有接口通过验收案例证明适用时，才做薄层复用。
- 新前台必须区分企业事实、第三方公开信息和概念演示；概念视觉不得冒充真实产品、设备、厂房、工艺或测试结果。
- 公司与产品主张必须有可访问来源及适用边界；模型输出不能绕过本地证据门禁。
- 新前台先在隔离预览中验收，未经批准不覆盖旧系统、正式页面、资料清单或索引。

## 后果

正面影响：

- 两种用户路径和产品语言保持清晰；
- 旧化工系统的证据能力与回归测试不会被展示站改造破坏；
- 新展示前台可以使用更适合公开品牌表达的技术与视觉方案；
- 任一方向停止时都不要求迁移或回滚另一套产品。

代价：

- 仓库暂时包含两套前台及各自规范；
- 在出现真实复用需求前会有少量独立的展示数据和交互代码；
- 提交和测试必须明确属于哪一套产品，避免跨边界修改。

## 回退与替代条件

- 新展示方向未获认可时，可以停止或移除其独立实现，不修改旧 Chemical Trade AI Copilot。
- 若未来决定拆分仓库，应先证明同仓维护造成持续构建、权限、发布或依赖冲突，并提供历史、测试和资产迁移方案。
- 若未来需要共享证据服务，应先以具体调用方、固定失败案例和安全边界证明独立实现不足；不得仅为了“统一架构”预建公共平台。
