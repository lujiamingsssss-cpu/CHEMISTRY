# ADR 0002：化工询盘台拆分为独立仓库，静态展示站只保留记录

Status: Accepted
Date: 2026-09-16

## 背景

- 本仓库同时维护公开展示前台与化工询盘台，两者隔离关系见 ADR 0001。
- 询盘台此后已具备独立的产品边界、验收用例与双语界面；用户已为其建立独立远端仓库
  `https://github.com/lujiamingsssss-cpu/INQUIRY`。
- 拆分前，本地同时存在**三份**询盘台代码副本，且其中一份的 Git 元数据已失效、长期无版本控制：

  | 路径 | 性质 |
  |---|---|
  | `F:\化工询盘台` | 新建的正式副本，远端为 `INQUIRY` |
  | 本仓库 `src/chemical_trade_copilot/` | 早期（阶段三时代）副本，随本仓库维护 |
  | 本仓库 `.worktrees/technical-review-o1/` | 双语版来源，`.git` 指向已不存在的 `F:/外贸化工/...`，无法执行任何 Git 操作 |

## 备选方案

### A. 继续同仓维护两份产品

构建、测试、发布与权限互相牵动；本地副本只会继续增多，且"哪一份才是正式版"会持续失真。

### B. 就地改造或删除询盘台

仓库表面更简单，但会破坏已验收的证据治理能力、回归用例与历史，且与"静态站未来仍要接上它"的目标冲突。

### C. 拆分为独立仓库，本仓库只保留记录与对接契约（采用）

## 决定

采用方案 C：

- 询盘台的**唯一正式本地副本**为 `F:\化工询盘台`，远端为 `https://github.com/lujiamingsssss-cpu/INQUIRY`。
- 本仓库不再承载询盘台的开发、测试、资料清单与发布；**本 ADR 与 `PROJECT_SPEC.md` 顶部的指引，
  构成本仓库关于询盘台的唯一权威记录**。
- 未来公开展示站接入询盘台，**只允许通过 URL / HTTP 契约对接**（例如以查询参数把询盘文本带过去的深链），
  不得复制、导入、分叉或反向依赖询盘台源码。
- 只有出现**真实调用方 + 固定失败案例**，并证明该契约不足时，才评估更紧密的集成；
  不得为"统一架构"预建共享平台层。

## 后果

正面影响：

- 两侧的构建、测试、发布与依赖互不牵动；
- 询盘台获得独立版本控制与可推送远端，不再依赖某一台本机目录；
- 本仓库职责单一（公开展示与 TWINKLE）。

代价：

- 跨产品的改动需要在两个仓库分别操作，无法用一次提交表达；
- 公开展示站的"技术询盘"入口在对接实现前仍是占位；
- 本仓库暂时保留一份已过时的询盘台副本，直到清理完成。

## 本仓库遗留物与处置

| 遗留物 | 处置 |
|---|---|
| `src/chemical_trade_copilot/`、`tests/` 中的询盘台部分、`materials_catalog.json`、`PROJECT_SPEC.md` 正文、`docs/UI_STYLE_GUIDE.md`、`docs/MATERIAL_EXPANSION_RUNBOOK.md` | **待清理**。内容已保全于 `F:\化工询盘台`（基线提交 `70a9227`）。清理会同时影响本仓库现有测试与工作流，因此需要单独确认后再执行 |
| `.worktrees/technical-review-o1/` | 无有效 Git 元数据。内容已保全于 `F:\化工询盘台`。**该目录内含 `.env.local`，不得复制、提交或外发**。建议确认后删除 |
| 工作区中 2 个未提交改动（`src/chemical_trade_copilot/inquiry_analysis.py`、`tests/test_inquiry_analysis.py`，内容为关闭思考模式与显式超时） | 同一修复已在询盘台仓库提交 `2d7e68b`。本仓库这一份建议随遗留物清理一并移除，不再单独维护 |

## 回退与替代条件

- 拆分未获认可时：删除 `INQUIRY` 远端与本地副本，回到同仓维护。本仓库除本 ADR 外未做任何改动，回退无成本。
- 若未来出现"跨仓协作造成持续构建、权限、发布或依赖冲突"的真实证据，再评估 monorepo、子模块或其他方案，
  不得仅凭偏好迁移。
