# TWINKLE 光学收集模块 Blender 流程样机与睿扬替换计划

> **For agentic workers:** 执行本计划时先使用 `executing-plans`；不得在资料未通过入口门禁前开始建模。复选框用于跨会话跟踪，但未经用户明确要求不得提交、推送或部署。

**Goal:** 先审计 TWINKLE 开放资料中的光学收集模块；只有确认 CAD 可完整分件导入且许可要求可满足后，才在 Blender 5.2 中制作一套明确标注来源的流程样机，后续再依据睿扬真实资料替换为正式产品。

**Architecture:** 第一阶段以“开放资料包审计—模块边界确认—CAD 转换验证—灰模—高质量几何—材质—装配控制—分镜预演—正式动画—灯光渲染—工程交付”为单一制作链，只制作资料充分的 TWINKLE 光学收集模块。第二阶段不是在流程样机上换 Logo，而是在取得睿扬真实资料后替换模型结构、材质与正式说明；任何与本计划冲突的用户后续资料均优先。

**Tech Stack:** Blender 5.2 LTS、Blender Python API、官方 Blender MCP、EEVEE Next（审看）与按实际质量/时长决定的 EEVEE Next 或 Cycles（最终渲染）。

## 1. 第一版对象、事实源与品牌边界

### 当前对象决定

- 用户当前调研结论认为：公开资料支持睿扬具备红外加工、镀膜、光学设计和镜头装配能力，可交付红外镜头总成；目前没有充分证据将其描述为带探测器和电子系统的完整红外热像仪制造商。本计划把这项结论作为用户提供的工作前提，不外推更强主张。
- 普通商业红外镜头的公开 STEP、尺寸图和照片通常不足以证明内部镜组、装配顺序和分件关系，因此不能据此制作“真实拆解”动画。
- 第一版候选对象改为 TWINKLE 开源双光子显微系统中的“光学收集模块”，不限定为红外产品；选择原因是该模块的机械、光学和装配资料与本项目训练目标更匹配。
- 制作边界只包括审计后确认资料完整的收集模块：金属外壳、镜筒、透镜、红外截止滤光片、二向色镜、波段滤光片、探测器及其有资料支持的装配结构。
- TWINKLE 使用的商业显微物镜不拆内部镜组；任何未被实际文件支持的商业件同样作为不可拆分整体。
- OpenFlexure Microscope 保留为备选。其装配资料和开放许可明确，但整体视觉偏 3D 打印科研设备，现阶段不优先用于高级金属光学产品流程样机。

### 已核对的公开入口

- [PLOS ONE 论文：TWINKLE](https://journals.plos.org/plosone/article?id=10.1371/journal.pone.0318924)明确说明 CAD、BOM、光学设计、装配说明等资料公开，并指向项目仓库；论文正文采用 CC BY 许可。
- [BrainCOGS/Microscope 官方仓库](https://github.com/BrainCOGS/Microscope)列出 `cad`、`parts`、`zemax` 和 `documentation` 等目录，并声明 CC BY 4.0。仓库首页明确列出的主装配格式是 Fusion 360 `.f3d` 和 Autodesk Inventor `.iam`；是否另有 STEP 等中性格式、以及能否保留完整层级转换到 Blender，必须由 Task 1 检查实际下载包，当前不作肯定判断。
- [OpenFlexure Microscope 装配入口](https://build.openflexure.org/openflexure-microscope/master/)提供多种配置的装配说明、源文件入口和交互三维视图，并标示 CERN-OHL-S-2.0；仅在 TWINKLE 审计不通过或用户改选时启动它的独立资料审计。

### 展示与品牌边界

- 第一版统一标注为“基于开放光学系统资料制作的流程样机”或等义文字，并保留 TWINKLE 来源和许可归属；
- 不添加睿扬 Logo，不使用睿扬产品型号，不把样机静帧或动画称为睿扬真实产品；
- 可以说明它用于验证光机产品的建模、拆解、标签、聚焦、光路和复位流程，但不能以结构相似为由宣称它代表睿扬具体产品；
- 后续拿到睿扬资料后，重新执行真实产品资料审计，再替换结构、材质和正式说明。

### 通用事实优先级

资料优先级固定为：

1. 用户在执行时实际提供的文件、说明和批准；
2. 公司技术人员或老板对本产品的明确确认；
3. 公司对客户公开的规格书、图纸、宣传资料和原始照片；
4. 公司官网与展会主办方公开资料；
5. 经 Task 1 核验的 TWINKLE 官方开放资料；
6. 本计划中的默认部件、镜头和动画设想。

因此：

- 实际资料与本计划冲突时，实际资料优先；
- 实际产品不是红外镜头时，按真实产品重做结构分解，不强套镜组模板；
- 实际只有外观资料时，只制作外观模型和不暴露内部的动画；
- 实际允许展示的部件少于四个时，减少拆解单元，不凑数；
- 实际资料足以支持更多部件时，先提交新的拆分表供用户批准，不自动扩大范围；
- 任何推断必须在审看说明中标记为“展示性简化”或“概念示意”。

## 3. 后续替换睿扬真实产品时才向公司索取的资料

本节不是 TWINKLE 流程样机的当前开工门槛，只在后续替换为睿扬真实产品时使用。对公司的询问只保留会直接决定模型形状、拆解关系和渲染外观的资料。产品卖点、技术参数、应用场景、中英文解说、展会文案、宣传册和同行动画参考均不作为 Blender 开工门槛；前期需要文字时使用明确标记的临时名称与临时说明，收到官方信息后再替换，不把临时文案当成事实发布。

可直接发给老板的最小清单：

> 麻烦确定一款要展示的产品，并尽量一次性提供下面资料。只用于制作该产品的三维模型、拆解动画和渲染；产品解说和宣传文字暂时不需要。
>
> 1. 产品名称或内部代号，以及这次要按真实产品制作还是允许做展示性简化。
> 2. 优先提供可查看的三维装配文件，例如 STEP、STP、IGES、Parasolid 或其他 CAD 格式；最好能保留需要拆开的独立零件。若确实没有三维文件，请提供产品前、后、左、右、上、下六个方向的清晰原图，并补充接口、镜片、旋钮等关键细节近照。照片尽量正对产品拍摄，不要使用广角、美颜或透视很强的宣传图。
> 3. 至少提供产品总长、最大直径或宽高等总体尺寸，以及安装接口和会在动画中拆开的主要部件尺寸。可直接给尺寸图，也可在正交照片中放置直尺作为比例基准。
> 4. 提供允许展示的零件分界、装配顺序和拆出方向。最理想的是爆炸图、剖面图或可分零件的装配 CAD；没有图纸时，可在照片上编号并用箭头标明“哪一件从哪里、向什么方向拆出”。
> 5. 提供产品真实颜色、材质和表面效果的参考，例如黑色阳极氧化、喷砂金属、抛光金属、玻璃及镀膜颜色。自然光下的原始照片即可，避免只提供严重调色的宣传图。
>
> 如果其中有只能作为内部建模参考、不能出现在最终画面的内容，请随文件标注；这不是额外的建模资料要求。

这五项的判定规则：

- 第 2、3 项决定是否能可靠还原外形与比例；两者都缺失时不得开始真实产品建模；
- 第 4 项决定是否能制作“真实拆解”；缺失时只制作完整外观与转台动画，不猜测内部构造；
- 第 5 项决定是否能制作可信的正式材质；缺失时只交付中性灰模或明确标注为暂定材质的预览；
- 资料使用限制是信息安全门禁，但不计入建模输入；未确认前，只能在本地检查资料，不输出包含未确认结构的渲染；
- 公司若提供结构完整、比例正确且可拆分的装配 CAD，第 2、3、4 项可由同一份 CAD 同时满足，但仍需确认第 5 项；
- 只收到照片时，六向原图、至少一个真实尺度和可见结构说明共同构成最低外观建模依据，单张宣传图不够。

执行时建立一份会话内资料清单，不把敏感内容复制到仓库 Markdown。每个文件只登记文件名、原始位置、对应产品、可用范围，以及它能支持和不能支持的模型结论。

## 4. 目标工程结构

第一版流程样机主工程建议保存到：

`E:\Blender\Projects\TWINKLE_Collection_Prototype\TWINKLE_Collection_Prototype_Master.blend`

参考资料保留在：

`E:\Blender\Projects\TWINKLE_Collection_Prototype\references\`

渲染输出写入：

`E:\Blender\Projects\TWINKLE_Collection_Prototype\renders\`

TWINKLE 下载包、转换中间件和渲染工程均保存在该独立项目目录，不复制进 Git 仓库。后续睿扬原始图纸、客户资料或未公开参数也不得进入 Git。

Blender 集合结构：

```text
00_REFERENCE
01_PRODUCT
02_CONTROLS
03_LABELS
04_STAGE
05_CAMERAS
06_OUTPUT
```

其中 `01_PRODUCT` 的子集合和对象名称在 Task 1 后按 TWINKLE 光学收集模块的真实装配层级确定；商业物镜和资料不完整的商业件保持单一黑盒对象。
